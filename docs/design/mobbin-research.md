# Mobbin research — Jalanin

Research conducted in Mobbin MCP on 12 October 2026. Results were inspected as screen previews and flow galleries; findings below distinguish observed references from Jalanin-specific recommendations. The research is pattern inspiration, not a pixel-level reproduction.

## Recruiting and applications

| Product / reference | Observed pattern | Why it works | Jalanin adaptation | Trade-offs |
|---|---|---|---|---|
| Remote — [Job detail flow](https://mobbin.com/flows/7077be26-97ef-4f9c-842d-6544f53c7426) | Search results use compact metadata rows; detail keeps role content primary and groups facts in a side panel with repeated apply actions. | Users can scan opportunities, then consult concise facts while reading longer role content. | Keep internship description readable, collect city/country/dates/category in a compact summary, and keep Apply visible on desktop/mobile. Never show pricing. | A sticky side panel can consume too much mobile space; collapse it into an inline summary. |
| Braintrust — [Applying for a job](https://mobbin.com/flows/06fe98c4-3702-4f9c-842d-8ea69e73a104) | Application tasks are paired with document upload, clear loading/complete feedback, and an explicit completion confirmation. | Progress and upload status reduce uncertainty during a high-stakes flow. | Preserve server-validated upload behavior and explain what was saved/submitted. Use Jalanin’s approved fields and application states only. | The reference includes unrelated screening/payment-like surfaces; do not transfer those features. |
| Contra — [Applying a job](https://mobbin.com/flows/287401eb-e111-4356-8a94-9634f92eeae7) | Form context remains close to the opportunity, with a clear cancel/submit boundary. | Users retain the job context and can understand what they are sending. | Show opportunity title and a review summary beside application sections on wide screens; simplify to stacked layout on mobile. | Dialog treatment is inappropriate if the application is long; retain full-page form semantics. |
| Wellfound — [Job post](https://mobbin.com/flows/da1a2fd9-d1af-418c-becb-f6210e1b2f2f) | Search criteria are visible, detail fields are scannable, and application context remains adjacent to the listing. | Supports comparison and quick eligibility assessment. | Use filter form labels and structured detail facts; do not expose salaries or application deadlines as hard cutoffs unless approved. | Dense metadata can obscure the actual role; prioritize summary and requirements. |

## Observed UX opportunities in existing Jalanin implementation

Inspection of source routes found functional coverage across public, authentication, student, and admin journeys. The initial shared style is mostly browser-default utility styling (white page, emerald buttons, uniform borders), with a dense green hero, no formal semantic tokens, little differentiated hierarchy between listing cards and admin surfaces, and horizontal mobile navigation. Existing search, server-side state, secure auth, storage, and workflow integration should be preserved. No supplied public brand assets were found.

## Synthesis (recommendations, not Mobbin observations)

- Public discovery: editorial heading hierarchy + compact filter rail + role cards with clear location/date facts.
- Detail: role content first, fact summary close by, persistent but non-obstructive Apply action.
- Application: grouped single-page form favored initially because drafts currently persist as one application record; preserve values and avoid fake step percentages. A review summary may be used where the existing model supports it.
- Student dashboard: record list and precise status timeline; no charts or invented progress.
- Admin: stable compact navigation, real counts, scan-friendly table on desktop and equivalent compact records on mobile; make re-review and unread state explicit.
- Auth: narrow form column with labels and clear recovery/success feedback.
- Surfaces: predominantly solid backgrounds; reserve blur/translucency for short headers/overlays only.
